# Vino — сканер российских вин по фотографии

Сервис должен распознавать бутылку российского вина по фотографии этикетки и сразу открывать карточку нужной позиции из каталога [«Своё Вино»](https://vino-svoe.ru/wines).

> Пользователь фотографирует этикетку у полки — сервис за несколько секунд возвращает одну наиболее вероятную карточку вина, а не список похожих вариантов.

## Статус проекта

Готовы этапы 1–6: аудит каталога, synthetic validation, гибридный распознаватель DINOv2 + SIFT + OCR, калиброванный сценарий `match / alternatives / not_found`, FastAPI и три адаптивных интерфейса `/`, `/calib`, `/admin`. После добавления глобального OCR retrieval последовательный HTTP-прогон из 10 кадров показал p50 **1 500 мс**, p95/max **2 387 мс** — все кадры ниже лимита 10 секунд.

## Быстрый запуск приложения

```powershell
.\app\start.ps1
```

После прогрева откройте `http://127.0.0.1:8000`. Модель и артефакты загружаются только локально; Swagger находится на `http://127.0.0.1:8000/api/docs`.

## Задача

Решение должно закрывать три бизнес-задачи:

1. **Распознавание вина по фотографии** в реальных условиях: под углом, с бликами, при плохом освещении и на фоне полки.
2. **Мобильная карточка найденного вина** в стилистике портала «Своё Вино».
3. **Удержание пользователя после поиска** за счёт полезной дополнительной функции — например, цифрового сомелье или подбора аналогов.

Главная сложность — большое количество визуально близких позиций. В рамках одной серии могут отличаться год, сезон, сорт или категория, тогда как дизайн этикетки остаётся почти одинаковым.

## Требуемая функциональность

- загрузка фотографии из галереи или с камеры;
- нормализация изображения перед распознаванием;
- поиск одной наиболее подходящей позиции в каталоге средствами CV;
- при необходимости — OCR как дополнительный сигнал;
- выдача полной карточки вина в JSON для фронтенда;
- расчёт уверенности и метрик для top-1 и top-5 результатов;
- мобильная страница карточки и дополнительный пользовательский сценарий после поиска;
- обработка неизвестного вина: честный отказ либо подбор наиболее похожих позиций и аналогов.

## Контракт для проверки

Скрипт кейсодержателя будет последовательно отправлять изображения в локально запущенный сервис. Для каждого изображения ожидается один лучший результат в плоском JSON-формате:

```json
{"slug": "wine-slug"}
```

Время ответа измеряет проверяющий скрипт. Предсказания будут сопоставляться с закрытой таблицей правильных `slug`.

## Критерии качества

| Критерий                          | Ожидание                                                  |
| --------------------------------- | --------------------------------------------------------- |
| Совпадение на контрольной выборке | 90–100%                                                   |
| Основной результат                | один уверенный top-1 `slug`                               |
| Разделимость                      | заметный и стабильный отрыв top-1 от ближайших кандидатов |
| Время ответа                      | до 3 секунд; скорость считается преимуществом             |
| Демонстрация                      | локально, без обязательного внешнего деплоя               |

Проверка проводится на публичном и приватном наборах полевых фотографий. Приватный датасет запускается кейсодержателем во время контрольного онлайн-звонка.

### Структура файлов

```text
data/parser/
├── images/       # эталонные изображения бутылок, по одному на slug
├── wines.json    # исходный снимок каталога и метаданные сбора
└── wines.sqlite  # те же данные в нормализованном виде
```

JSON содержит корневые метаданные и массив `wines`. В SQLite данные разнесены по таблицам:

- `wines` — основная карточка;
- `grapes` — сорта винограда;
- `dishes` — гастрономические сочетания;
- `metadata` — источник, время и полнота сбора.

Для полей, по которым удобно фильтровать каталог, в SQLite уже созданы индексы: регион, категория, цвет, производитель и рейтинг.

### Поля карточки вина

| Поле                                    | Назначение                                             |
| --------------------------------------- | ------------------------------------------------------ |
| `slug`                                  | уникальный идентификатор и целевой класс распознавания |
| `title`                                 | название вина                                          |
| `manufacturer`, `manufacturer_slug`     | производитель                                          |
| `region`, `category`, `color`           | основные характеристики                                |
| `public_rating`, `rating`               | доступные рейтинги                                     |
| `alcohol`, `alcohol_max`, `temperature` | параметры подачи и крепости                            |
| `description`                           | описание вкуса, аромата и технологии                   |
| `grapes`                                | сорта винограда                                        |
| `dishes`                                | рекомендуемые блюда                                    |
| `image_local`                           | путь к локальному эталонному изображению               |
| `image_source_url`, `image_alt`         | исходное изображение и альтернативный текст            |
| `source_url`                            | страница карточки на сайте                             |

### Первичный аудит качества данных

- все 2 025 `slug` уникальны;
- все 2 025 ссылок `image_local` ведут на существующие файлы;
- лишних изображений, не связанных с карточками, нет;
- все WebP-файлы успешно декодируются; 1 922 изображения имеют альфа-канал;
- эталоны в основном представляют собой чистые каталожные вырезки бутылок, а не полевые фотографии этикеток — между обучающими эталонами и проверочными кадрами есть заметный domain gap;
- найдено 108 групп с одинаковым `title` без учёта регистра и лишних пробелов — название нельзя использовать как уникальный ключ;
- найдено 24 пары побайтово одинаковых изображений у разных `slug`; такие позиции требуют текстовых или контекстных признаков;
- `public_rating` отсутствует у 1 127 позиций, `rating` — у 1 857;
- `temperature` заполнена только у 7 позиций;
- значения крепости `108` и `135` как минимум в трёх карточках выглядят как потерянная десятичная точка (`10.8` и `13.5`);
- поле `manufacturer_slug` отсутствует у 9 карточек.

Перед обучением или индексацией стоит сформировать отдельный отчёт валидации, исправить числовые аномалии и явно разметить группы near-duplicates. Для приближения к реальным входным данным понадобятся аугментации перспективы, бликов, освещения, размытия и фона либо отдельный набор полевых снимков. Исходный снимок лучше сохранять неизменным, а очищенную версию строить отдельным воспроизводимым этапом.

## Техническая основа

- Python 3.12+;
- данные доступны как JSON и SQLite;
- использование нейросетей не обязательно: допустимы классические CV/OCR-подходы;
- каталог пополняется примерно на 50 позиций в день, но скорость переиндексации не является главным критерием текущего этапа.

## Рекомендуемое направление разработки

1. Зафиксировать публичный validation-набор полевых фотографий и метрики top-1/top-5.
2. Построить базовый retrieval по визуальным эмбеддингам.
3. Добавить нормализацию перспективы, освещения и бликов.
4. Переранжировать ближайших кандидатов с помощью OCR и метаданных.
5. Откалибровать порог «не найдено» и уверенность top-1.
6. Обернуть инференс в API с минимальным контрактом `{"slug":"..."}`.
7. Добавить мобильную карточку и дополнительный retention-сценарий.
