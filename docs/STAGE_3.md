# Этап 3: визуальный retrieval baseline

Реализован поиск по всему каталогу без обучения классификатора на 2 025 классов. Для каждого
эталона сохраняются глобальные `CLS`-embedding и локальные patch-токены этикетки. Запрос
обрабатывается в трёх масштабах: полный кадр, средний crop и крупный crop этикетки.

Главный приоритет эксперимента — качество. Время измеряется, но допустимым исследовательским
потолком считается 10 секунд на фотографию. Итоговый вариант работает намного быстрее.

## Сравнение моделей

Все результаты получены на одной исправленной synthetic validation-выборке из 2 025 кадров,
на RTX 4060 8 ГБ, с входом 518×518. Индексы и предсказания сохранены в
`data/artifacts/stage3/`.

| Модель       | Параметры | Лучший режим               |      Top-1 |      Top-5 |       MRR | Batch, мс/кадр |          Один кадр, мс |
| ------------ | --------: | -------------------------- | ---------: | ---------: | --------: | -------------: | ---------------------: |
| DINOv2-small |    21 млн | multiscale CLS             | **71,36%** | **92,40%** | **0,801** |          73,96 | 88,12 mean / 92,24 p95 |
| DINOv2-base  |    86 млн | multiscale CLS + 20% patch |     68,59% |     90,17% |     0,776 |         120,96 |                 143,27 |
| DINOv2-large |   300 млн | multiscale CLS + 20% patch |     49,98% |     73,28% |     0,590 |         291,24 |                 336,61 |

Больший backbone не оказался лучше для каталожных бутылок. Рабочим вариантом выбран
`facebook/dinov2-small`: он одновременно дал лучший top-1/top-5 и минимальную задержку.
Загрузка весов не входит в задержку запроса — будущий API должен загрузить и прогреть модель
один раз при старте.

## Вклад отдельных изменений

Для DINOv2-small:

| Режим                         |      Top-1 |      Top-5 |
| ----------------------------- | ---------: | ---------: |
| Только CLS полного кадра      |     66,32% |     90,22% |
| CLS полного кадра + двух crop | **71,36%** |     92,40% |
| Multiscale CLS + 20% patch    |     70,42% |     92,40% |
| Multiscale CLS + 35% patch    |     68,99% | **92,49%** |
| Multiscale CLS + 50% patch    |     66,81% |     91,16% |
| Только patch-MaxSim           |     38,77% |     65,88% |

Несколько масштабов дали полезный прирост `+5,04` процентного пункта top-1. Patch-токены
реально сравниваются через MaxSim внутри глобального top-30, однако ни один их вес не улучшил
главную метрику top-1. Поэтому patch-rerank сохранён как опциональный эксперимент, а в CLI по
умолчанию используется чистый multiscale CLS (`--patch-weight 0`).

Patch-индекс хранит 7×7 локальных нормализованных векторов на эталон. Rerank выполняется только
для 30 кандидатов, поэтому его вычислительная стоимость невелика и не зависит от полного размера
каталога.

## Качество победителя по профилям

| Профиль       |  Top-1 |  Top-5 |
| ------------- | -----: | -----: |
| `background`  | 80,34% | 99,31% |
| `perspective` | 82,76% | 98,97% |
| `glare`       | 77,85% | 99,31% |
| `crop`        | 83,39% | 99,31% |
| `compression` | 73,01% | 97,58% |
| `blur`        | 64,01% | 87,54% |
| `combined`    | 38,06% | 64,71% |

Главный резерв следующего этапа — `blur`, `combined` и визуально одинаковые серии. Для них
увеличение DINOv2 не помогло; нужны локальная геометрия и OCR.

## Построение индексов

Основной индекс:

```powershell
uv run vino-build-index --device cuda --batch-size 16
```

Воспроизведение Base и Large:

```powershell
uv run vino-build-index `
  --model facebook/dinov2-base `
  --device cuda --batch-size 8 `
  --output-dir data/artifacts/stage3/dinov2-base

uv run vino-build-index `
  --model facebook/dinov2-large `
  --device cuda --batch-size 4 `
  --output-dir data/artifacts/stage3/dinov2-large
```

При первом запуске веса скачиваются с Hugging Face. После этого можно использовать
`--local-files-only`. Индексы Small/Base/Large занимают примерно 81/160/212 МБ соответственно.

## Полная оценка

```powershell
uv run vino-baseline `
  --device cuda --batch-size 16 `
  --local-files-only `
  --candidate-count 30 `
  --index data/artifacts/stage3/dinov2-small/index.npz `
  --output-dir data/artifacts/stage3/baseline-small-quality
```

Для каждого backbone сохраняются предсказания и стандартные evaluation-отчёты для:

- `cls_full`;
- `cls_multiscale`;
- `patch_only`;
- `cls_patch_20`, `cls_patch_35`, `cls_patch_50`.

## Распознавание

Итоговая quality-first конфигурация включена по умолчанию:

```powershell
uv run vino-recognize path/to/photo.jpg --device cuda --local-files-only
```

Она возвращает лучший `slug`, top-5, scores и измеренную задержку. Patch-rerank можно включить
явно, например:

```powershell
uv run vino-recognize path/to/photo.jpg `
  --device cuda --local-files-only `
  --patch-weight 0.20
```

Поддерживаются JPEG, PNG, WebP и BMP. Модель и индекс должны совпадать; CLI автоматически
читает имя модели из индекса.

## Ограничения

- 71,36% — лучший текущий synthetic baseline, но целевые 90% top-1 ещё не достигнуты.
- Выбор модели сделан по synthetic-набору и должен быть перепроверен на реальных полевых фото.
- Порог «не найдено» намеренно отсутствует до этапа 5.
- Веса моделей хранятся в Hugging Face cache, а не в репозитории.
