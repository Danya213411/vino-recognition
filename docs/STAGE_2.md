# Этап 2: синтетическая validation-выборка

Генератор превращает чистые каталожные изображения бутылок в воспроизводимые сцены, приближённые к фотографиям у винной полки.

Исходные файлы в `data/parser/` не изменяются. Результат сохраняется в `data/synthetic/stage2/`.

## Запуск

Перед генерацией должен быть построен manifest первого этапа:

```powershell
uv run vino-audit
uv run vino-generate-synthetic
```

По умолчанию создаётся один кадр для каждого из 2 025 `slug` размером 512×512. Профили равномерно распределяются по каталогу.

Для короткой проверки:

```powershell
uv run vino-generate-synthetic --limit 20 --output-dir data/synthetic/smoke
```

Для полного покрытия каждым профилем каждого вина:

```powershell
uv run vino-generate-synthetic --variants-per-wine 7
```

Такой запуск создаст 14 175 изображений и потребует заметно больше дискового пространства.

## Профили преобразований

| Профиль | Основное воздействие |
|---|---|
| `background` | бутылка на процедурном фоне полки |
| `perspective` | сильное перспективное искажение |
| `glare` | вытянутый блик, ограниченный маской бутылки |
| `crop` | крупный масштаб и частичный выход бутылки за кадр |
| `compression` | уменьшение разрешения и сильное JPEG-сжатие |
| `combined` | перспектива, блик, occlusion и компрессия без blur |

Для всех профилей также меняются положение, масштаб, яркость и контраст.

Перспектива строится проекцией плоскости через повороты по трём осям, а не независимым
сдвигом четырёх углов. Каждый кадр проходит геометрический QA: проверяются выпуклость,
отношения противоположных граней, видимая площадь и допустимый выход за границы. Результат
проверки и углы поворота записываются в `transformations.geometry.qa` manifest-файла.

## Воспроизводимость

Seed каждого кадра вычисляется из:

```text
global seed + slug + variant index
```

Поэтому изображение конкретного `slug` не меняется при перестановке строк manifest. Одинаковая конфигурация создаёт побайтово одинаковые JPEG-файлы.

Параметры можно изменить:

```powershell
uv run vino-generate-synthetic `
  --seed 20260920 `
  --image-size 640 `
  --jpeg-quality 90 `
  --variants-per-wine 1
```

## Выходные файлы

| Путь | Назначение |
|---|---|
| `data/synthetic/stage2/images/` | сгенерированные JPEG-файлы |
| `data/synthetic/stage2/synthetic_manifest.jsonl` | правильный `slug`, профиль, SHA-256 и параметры каждого кадра |
| `data/synthetic/stage2/generation_report.json` | конфигурация и статистика генерации |
| `data/synthetic/stage2/generation_report.md` | краткая сводка |

Все записи получают split `validation`. Генератор не создаёт обучающую часть, поэтому производные одного исходного изображения не могут одновременно попасть в train и validation.

## Связь с evaluator

На третьем этапе распознаватель должен сохранить для каждого synthetic sample:

- `sample_id`;
- `image`;
- `expected_slug`;
- `profile`;
- `predictions`;
- `latency_ms`.

`vino-evaluate` уже строит отдельный breakdown по `augmentation_profile`, поэтому качество перспективы, бликов, crop, background и compression будет видно отдельно. Blur исключён из основной синтетической выборки после сравнения с 66 полевыми фотографиями; при необходимости он должен запускаться отдельно как stress-test.
