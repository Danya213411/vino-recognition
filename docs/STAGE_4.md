# Этап 4: локальная геометрия и OCR

Реализован гибридный reranker для top-30 результатов DINOv2-small. Он проверяет локальное
совпадение этикеток через SIFT + ratio test + RANSAC и сопоставляет распознанный текст с OCR
эталона и полями `title`, `manufacturer`, `category`, `region`, `grapes`, `alcohol`.

## Итог

Полный эксперимент выполнен на той же synthetic validation-выборке из 2 025 кадров, что и
этап 3. Для настройки весов детерминированно выделены 399 кадров (19,7%); 1 626 кадров не
участвовали в настройке. Правильный slug присутствует в DINO top-30 для 96,89% запросов — это
верхняя граница текущего reranker без расширения списка кандидатов.

| Вариант             |      Top-1 |      Top-5 |       MRR | Held-out Top-1 |
| ------------------- | ---------: | ---------: | --------: | -------------: |
| DINOv2 multiscale   |     71,36% |     92,40% |     0,801 |         71,28% |
| DINOv2 + SIFT       |     73,98% |     91,85% |     0,815 |         73,92% |
| DINOv2 + SIFT + OCR | **75,46%** | **92,99%** | **0,829** |     **75,65%** |

Итоговый прирост top-1 составляет **+4,10 процентного пункта**, а held-out top-1 —
**+4,37 п.п.** Это не эффект подгонки только на calibration-части.

Оптимальные веса на calibration-наборе:

- embedding — 0,45;
- SIFT — 0,15;
- OCR — 0,40.

SIFT без OCR использует вес 0,50. Веса подбираются сеточным поиском с приоритетом top-1, затем
top-5 и только после этого меньшей доли дополнительных сигналов. Сырые оценки сохранены в
`data/artifacts/stage4/baseline/signals.npz`, поэтому веса можно пересчитать без повторного
запуска моделей.

## Визуально близкие группы

На 168 позициях из 68 near-duplicate групп гибрид повысил top-1 с 50,00% до 52,38%, а top-5 —
с 92,26% до 94,05%. На held-out части этих групп top-1 вырос с 48,51% до 51,49%.

У 48 позиций из 24 групп эталонные файлы побайтово одинаковы, хотя slug и метаданные различны.
Для таких пар изображение принципиально не содержит достаточного сигнала: top-1 вырос лишь с
31,25% до 33,33%. Их нельзя честно довести до 100% без нового изображения, дополнительного
контекста или исправления каталога.

Главный оставшийся провал — профиль `combined`; OCR и SIFT не восстанавливают информацию,
которая одновременно сильно размыта, обрезана и искажена.

## Индексы

Эталонный индекс строится один раз:

```powershell
uv run vino-build-stage4-index --workers 3
```

Он содержит 911 198 RootSIFT-дескрипторов без пустых эталонов. RapidOCR распознал текст у
2 001 из 2 025 изображений: всего 8 291 строка. Используется tiny-детектор PP-OCRv6 и mobile
Cyrillic-recognizer PP-OCRv5. OCR понимает кириллицу, латиницу и цифры одной моделью.

Артефакты:

- `data/artifacts/stage4/index/sift_index.npz` — 230,5 МБ;
- `data/artifacts/stage4/index/reference_text.jsonl` — OCR и нормализованные метаданные;
- `data/artifacts/stage4/index/index_report.json` — статистика построения.

Полное построение на i5-9600KF заняло 92,9 с для SIFT и 858,5 с для OCR с тремя воркерами.
Это офлайн-стоимость обновления каталога, а не задержка пользовательского запроса.

## Воспроизведение абляции

```powershell
uv run vino-stage4 --workers 3 --candidate-count 30
```

Команда создаёт отдельные prediction/evaluation-отчёты для `embedding`, `embedding_sift` и
`embedding_sift_ocr`. Повторный подбор весов по уже рассчитанным сигналам:

```powershell
uv run vino-stage4 --reuse-signals --candidate-count 30
```

Основной отчёт находится в `data/artifacts/stage4/baseline/stage4_report.json`.

## Распознавание одного изображения

```powershell
uv run vino-recognize-hybrid path/to/photo.jpg --device cuda --local-files-only
```

CLI возвращает один лучший `slug`, top-5, итоговый score, отдельные embedding/SIFT/OCR scores,
число RANSAC-inlier и задержку каждого этапа. Модель, индексы и OCR должны загружаться и
прогреваться один раз при старте будущего API.

На 20 одиночных прогретых запросах на RTX 4060 + i5-9600KF:

| Метрика времени |  Значение |
| --------------- | --------: |
| Среднее         | 463,60 мс |
| p50             | 461,15 мс |
| p95             | 611,02 мс |
| Максимум        | 739,21 мс |

Потолок 10 секунд соблюдается с большим запасом; выполняется и первоначальная цель до 3 секунд.
Пакетный полный эксперимент дал throughput 442,14 мс/кадр, а консервативная оценка
последовательного выполнения по отдельным компонентам — 781,16 мс/кадр.

## Проверка кода

```powershell
uv sync --group dev
uv run python -m pytest -q
```

Сейчас проходят 11 тестов, включая нормализацию кириллицы/латиницы/чисел, OCR-score,
геометрически согласованный SIFT-match и работу масок сложных групп.

## Ограничения

- 75,46% измерены на синтетике; качество обязательно нужно проверить на реальных полевых фото.
- Даже идеальный reranker ограничен recall DINO top-30 (сейчас 96,89%).
- Побайтово одинаковые эталоны с разными slug неразрешимы только по изображению.
- Порог «не найдено» и калибровка уверенности относятся к этапу 5 и пока намеренно не добавлены.
